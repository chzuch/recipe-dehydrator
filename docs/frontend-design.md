# 前端设计文档 · 视频脱水机 v0.2

> 状态：**待用户确认**（确认前不动代码）
> 定位升级：从「视频脱水工具」→「个人菜谱库」。视频是获取渠道，菜谱库是资产。

---

## 1. 设计目标与原则

**三个真实使用场景**驱动全部设计：

| 场景 | 设备 | 环境 | 核心需求 |
|---|---|---|---|
| 🛒 买菜 | 手机 | 超市，单手 | 大勾选框、按区分组、家里有的不用看 |
| 🍳 做菜 | 手机/平板立在灶台 | 手上有油、距离一米 | 瞟一眼就懂、一步一屏、手势翻页、不锁屏 |
| 📖 浏览/管理 | 桌面或沙发 | 闲暇 | 翻菜谱、找菜、决定吃什么 |

**原则**：
1. **菜谱库优先**：默认首页是我的菜谱，不是脱水输入框
2. **一卡三模式**：同一张卡片，浏览/做菜/买菜三种看法
3. **移动优先**：手机是主战场，桌面是次要场景
4. **离线可用**：做过的菜没网也能看（PWA）

### 功能清单

| 功能 | 说明 | 数据来源 |
|---|---|---|
| 成品图封面 | 用**最后一步的截图**当封面 | step[-1].frame_path |
| 分类筛选 | 按主料自动归类（鸡肉/牛肉/排骨/汤/素），无需手动标签 | ingredients 里 category=主料 的首项 |

| 排序 | 置顶优先 → 最近做过 → 最新创建 | 组合排序 |

要点：

### 4.2 做菜模式 ⭐（核心价值）

```
┌──────────────────────────┐
│ ← 尖椒鸡丁    步骤 5/7 ▓▓░ │
├──────────────────────────┤
│ 用料：鸡肉✓ 辣椒✓ 花椒✓ …  │  ← 顶部一条可核对
├──────────────────────────┤
│                          │
│   🔥 炒制                 │
│                          │
│   5. 滑炒鸡肉   ← 超大字号  │
│   ┌────────────┐         │
│   │  截图/GIF   │         │
│   └────────────┘         │
│   油温七成热下鸡肉大火划散   │
│   ✅ 鸡肉全部变色           │
│   ⚠️ 油温要够热            │
│                          │
│ [◀ 上一步]    [下一步 ▶]   │  ← ≥64px 大按钮
└──────────────────────────┘
手势：左滑=下一步，右滑=上一步
屏幕常亮（WakeLock），字体三档可调
```

要点：
- 一步一屏，字号大到一米外可读
- 进度条 + 当前阶段名
- **步骤导航栏**：防止"一步一屏迷路"——
  - 桌面/平板横屏：右侧竖排步骤栏（序号+精简标题），当前步高亮，点击跳转；做完的步打勾变灰（兼进度指示）
  - 手机竖屏：空间不足，改为顶部**步骤圆点条**（●●●○○○），点圆点跳转
- 顶部用料条（勾选状态从买菜清单同步）
- 隐藏一切无关元素（历史/编辑/买菜）
- 移动端手势 + 屏幕常亮
- 步骤看不懂 → 该步仍有 ▶ 唤起播放器（小窗浮层，不打断流程）

## 5. 内嵌播放器技术方案（已定：B站 iframe）

- URL：`https://player.bilibili.com/player.html?bvid={bvid}&page=1&t={秒}&autoplay=1`
- 从 `recipe.source_url` 提取 bvid
- 点步骤 ▶ → 展开播放器 + 设置 src（含 t 参数）→ 自动播放对应秒
- 浏览模式：播放器嵌在卡片顶部；做菜模式：浮层小窗
- 抖音等多平台播放器：二期（多平台支持时统一抽象）

## 6. 移动端适配

| 断点 | 设备 | 布局 |
|---|---|---|
| <768px | 手机 | 单列；菜谱库 2 列网格；底部 Tab；按钮 ≥44px |
| 768–1024px | 平板 | 两列；侧边抽屉 |
| >1024px | 桌面 | 三栏（现有布局演进） |

触控与厨房细节：左滑/右滑翻步骤、WakeLock 常亮、字体三档、大点击区。

## 7. PWA 离线（F4）

- Service Worker 缓存：卡片 JSON + 截图（每张 ~2-5MB）
- 视频不缓存（iframe 在线播放）
- manifest.json → 可"添加到主屏"，像 App 一样打开菜谱库

## 7.5 部署形态与技术方案（已定）

**形态：电脑当服务器，手机/平板浏览器访问（局域网）**。

```
电脑（WSL，FastAPI+SQLite+截图）── 同一 WiFi ──→ 手机/平板浏览器
                                                http://<电脑IP>:8000
                                                「添加到主屏」→ 像 App
```

决策理由：
- ❌ 手机/平板直接安装：手机跑不动 Python 后端，做 App 需重写打包，不现实
- ❌ 只用电脑看：做菜在厨房，电脑不在厨房
- ✅ 电脑服务器 + 移动设备浏览器：手机零安装、数据集中（菜谱库单一事实源）、现有 Web 架构天然支持

技术栈（全部沿用现有，不引入新框架）：
- 前端：响应式 Web（HTML + 原生 JS），CSS 媒体查询断点适配
- 移动端 App 化：PWA（manifest + Service Worker）
- 后端/存储：FastAPI + SQLite（不动）

**WSL2 局域网访问**（部署时要处理的坑）：WSL2 默认 NAT，手机访问电脑 IP 进不到 WSL。两种解法：
1. 端口代理：`netsh interface portproxy add v4tov4 listenport=8000 listenaddress=0.0.0.0 connectport=8000 connectaddress=<WSL_IP>` + Windows 防火墙放行 8000
2. mirrored 网络模式（新版 WSL2）：`.wslconfig` 加 `networkingMode=mirrored`，WSL 与 Windows 共享网络栈，无需 portproxy

安全：仅家庭局域网，不暴露公网，无需认证（后续可选加 token）。

## 9. API 变更

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/cards/{id}/cook` | 「今天做了」打卡：cooked_count+1、更新 last_cooked_at |
| POST | `/api/cards/{id}/pin` | 置顶/取消置顶（toggle） |
| GET | `/api/cards` | 加查询参数：`?q=搜索词&category=鸡肉&sort=pinned` |
| 其余 | 沿用现有 | — |

## 10. 实施路线

| 阶段 | 内容 | 产出 |
|---|---|---|
| **F1** | schema 变更 + 菜谱库页（网格/搜索/分类/置顶/打卡 + API） | 默认首页变菜谱库 |
| **F2** | 内嵌播放器（iframe + t 跳转） | 步骤▶页内播放 |
| **F3** | 三模式详情页 + 移动端响应式（做菜一步一屏/买菜全屏/手势/常亮） | 厨房可用 |
| **F4** | PWA 离线 + 暗色 + 字体档位 | 无网可看 |

每阶段独立可验收：F1 完 → 菜谱库可用；F2 完 → 页内看视频；F3 完 → 厨房实战。

## 11. 验收标准（本设计文档）

1. 菜谱库为默认首页，网格卡片展示成品图封面，可搜索/分类/置顶/打卡
2. 点步骤 ▶ 在页面内播放原视频对应片段（不跳外链）
3. 手机上做菜模式一步一屏，可手势翻页，屏幕常亮
4. 手机买菜模式清单全屏、大勾选、调味料折叠
5. 全程测试保持全绿（pytest + ruff + mypy）
